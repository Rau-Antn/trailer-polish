План исправления именно текущего поиска, без переделки анимации и без замены `/lottie/search.json`:

1. Разделить состояния поиска
- `hover-preview`: навели мышь — раскрывается одно большое pill-окно, Lottie видна на всю площадь окна.
- `typing/open`: кликнули или поле в фокусе — Lottie скрывается, остаётся чистое поле ввода.
- `has-value`: введён текст — поиск остаётся раскрытым, результаты работают.

2. Убрать причину “старого текста/старого окна”
- Не показывать placeholder поверх Lottie в hover-состоянии.
- В hover-состоянии input будет невидим/неактивен, чтобы не было белого внутреннего поля и старого текста.
- Placeholder появится только после клика, когда пользователь реально вводит запрос.

3. Сделать Lottie на всё раскрытое окно
- `.search-lottie` останется внутри текущего поиска, но будет абсолютно растянута на весь раскрытый pill: `inset: 0; width: 100%; height: 100%`.
- SVG/canvas Lottie получит `width: 100%; height: 100%; object-fit: cover/contain` без сжатия в левую полоску.
- Закрытое состояние останется круглой кнопкой.

4. Исправить клик и работу поиска
- Клик по поиску больше не будет закрывать пустое поле сразу.
- Первый клик переводит поиск из hover-анимации в режим ввода и скрывает Lottie.
- Ввод текста вызывает текущий `renderResults`, результаты остаются рабочими.
- Escape/клик вне поиска закрывают только пустое поле; если введён текст — поле остаётся открытым.

5. Исправить ошибку управления Lottie в JS
- Сейчас проверяется `pop.classList.contains('is-open')`, хотя `is-open` стоит на `.search-wrap`; это ломает остановку анимации.
- Переведу запуск/остановку Lottie на состояния `.search-wrap`: hover запускает, click/focus останавливает и скрывает.

6. Проверка после правки
- На `/index.html` при viewport около `807×494` проверить: hover, click, ввод, Escape, клик вне поля.
- Итог должен быть таким: наведение = большое единое окно с Lottie на всю ширину; клик = Lottie пропала, поле ввода чистое и рабочее; текст/результаты не появляются в старом/лишнем окне.
