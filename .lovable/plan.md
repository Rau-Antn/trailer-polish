План исправления без переделки поиска с нуля:

1. Сделать раскрытие единым контейнером
- Открытым состоянием будет управлять `.search-wrap`, а не только внутренняя кнопка.
- При hover/focus/`.is-open` весь блок поиска станет одним полноширинным pill-окном рядом с кнопкой темы.
- Закрытое состояние останется круглой кнопкой.

2. Исправить Lottie-зону
- Не менять файл `/lottie/search.json` и не менять саму Lottie-анимацию.
- Убрать визуальное ощущение “тонкой полоски слева”: Lottie будет лежать поверх всей раскрытой области как часть единого окна.
- В закрытом состоянии Lottie останется в круглой кнопке; в раскрытом — не будет сжиматься, обрезаться или стоять отдельным узким слотомом.

3. Вернуть нормальную ширину раскрытия
- На текущем viewport около 807px раскрытый поиск будет шире текущего сломанного вида: примерно 300–320px, но с безопасным ограничением, чтобы не залезать на шапку.
- Для мобильных ширин оставить адаптивное ограничение `calc(100vw - …)`, чтобы поле не выходило за экран.

4. Убрать лишнее пустое окно
- Без введённого текста не показывать dropdown/пустую подсказку.
- Результаты/“ничего не найдено” показывать только после реального ввода.

5. Не ломать текущую логику поиска
- JS-логику фильтрации товаров, данные, синонимы и результаты не переписывать.
- Править только геометрию, классы открытого состояния и поведение hover/click.
- Клик оставляет поле раскрытым и ставит курсор; уход мыши при пустом поле сворачивает; введённый текст держит поиск раскрытым.

Технически:
- Основная правка: `public/css/style.css` в блоке `.search-wrap`, `.search-toggle`, `.search-lottie`, `.search-input`, `.search-popover`.
- Минимальная правка `public/js/main.js` только если нужно синхронизировать hover/click и закрытие без переписывания поиска.
- После правки проверить на `/index.html` при ширине около 807px: hover, click, ввод текста, пустое поле, Lottie на полном раскрытом окне.
